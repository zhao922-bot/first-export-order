# 12 人试玩验收包 · 组织者说明

本包准备的是采集流程和验收工具，尚无真人结果或顾问签核。适用 `0.10.0-slice` / `playtest-1`；冻结内容哈希和门槛见 [protocol.json](protocol.json)。不得把自动化样本、演示数据、招募空位填成真人记录。

## 材料与分工

| 材料                                                           | 使用者                | 用途                                         |
| -------------------------------------------------------------- | --------------------- | -------------------------------------------- |
| [PLAYER_GUIDE.md](PLAYER_GUIDE.md)                             | 玩家                  | 无答案的试玩、恢复和导出指引                 |
| [FEEDBACK_FORM.md](FEEDBACK_FORM.md)                           | 玩家                  | 体验评分、困惑、退出原因、问题复现           |
| [OBSERVER_SHEET.md](OBSERVER_SHEET.md)                         | 主持人                | 七关观察、帮助程度、阅读负担、异常与导出核对 |
| [manifest.template.json](manifest.template.json)               | 数据组织者            | P01–P12 名单、纳入条件及文件映射             |
| [PROFESSIONAL_REVIEW.md](PROFESSIONAL_REVIEW.md)               | 外贸顾问 / 内容负责人 | 逐项核对来源、业务因果和待修订内容           |
| [ACCEPTANCE_REPORT_TEMPLATE.md](ACCEPTANCE_REPORT_TEMPLATE.md) | 验收负责人            | 数值、真人反馈、专业签核及放行结论           |

只给玩家玩家指引和反馈表，不发组织者材料、答案、模拟策略或验收门槛。玩家按自己的判断选择，主持人只解释操作；不得为了通过率引导“稳妥路线”。专业路线覆盖在首局与后测结束后另做，不替换首局。

## 会前准备

1. 招募至少 12 名自报无外贸基础、未玩过本作的成年人，使用 P01–P12 匿名编号。建议 6 桌面、6 手机，记录浏览器和视口；手机模拟器不替代真人手机。替补从 P13 起，不复用撤回编号。
2. 向玩家说明本地教学记录内容、主动导出及可跳过测评/中止/撤回。征得同意后，把名单状态由 `pending` 改为 `enrolled`，填写三个确认项；拒绝或撤回者不提交数据。联系方式不放入本包。
3. 每人独立浏览器配置/设备，使用同一 URL 与冻结构建。共享电脑用新的独立浏览器配置，不覆盖他人的存档。不在主测期间升级内容、清理记录或使用无痕模式。
4. `pnpm install --frozen-lockfile`、`pnpm build`、`pnpm preview --port 4173 --strictPort`；访问 `http://127.0.0.1:4173/#/`。同 Wi-Fi 手机可用 `pnpm preview --host 0.0.0.0 --port 4173 --strictPort`，输入电脑局域网 IP；只在测试网络中开放，不需要公开部署。地址/端口变化会产生不同浏览器存储域。
5. 保存 `dist/`、构建日志、内容哈希、日期和本机 Node/pnpm 版本。`protocol.json` 的哈希匹配只能证明组织者使用的内容文件；旧导出没有内容哈希，仍须主持人记录实际构建来源。
6. 复制名单到 `work/human-study/manifest.json`，建立 `exports/`。填写统一 ISO UTC `observationAt`（例如 `2026-10-24T12:00:00Z`，新加坡时间加 8 小时）；截止时间不能早于任一导出。模板日期只是占位，必须换成实际观察时间。

## 每人安排（预留约 60 分钟）

- 说明和自报筛查约 3 分钟，前测约 2 分钟，七关经营按自然速度进行，后测约 2 分钟，反馈约 8 分钟。30–45 分钟是待检验目标，不是到点强制结束。
- 首页进入“前测并开始七关试玩”。不预习图鉴或答案，不在正式开局前练习。前测开始后不要重开；若重开，原首局仍保留，记录原因。
- 主持人按观察表记各关问题、连续阅读是否超过两屏、复盘理解、移动端遮挡；不强迫持续口述以免明显改变耗时。不人为制造资金问题或付款误判。
- 到任一正式结局做后测，再导出指标、填写反馈。提前退出也请导出；无后测如实留缺，不能代答、补猜或记为零分。
- 会后 24 小时在约定渠道向仍未完成者确认有无恢复，并请其主动提交最新导出。一次关页不能判定流失。此步骤由组织者执行，本工具不会联系玩家。
- 首局及后测结束后，才可选做刷新恢复 / E05 / 其他付款路线的专项，使用新局并单列。存档 JSON 与试玩指标 JSON 是不同文件，不要混用。

## 文件归档与批量汇总

原始导出保留不编辑，重命名成 `P01-01.json`、`P01-02.json` 等；把同一人的所有快照列入其 `exports`。`primaryRunId` 留 `null` 自动取最早完整模式开局，或填写核实后的同一首局 ID；不能指定更好的重开局。不要提交他人的浏览器历史。

```powershell
pnpm playtest:aggregate --manifest=work/human-study/manifest.json --input=work/human-study/exports --out=outputs/human-study-01
pnpm playtest:aggregate --manifest=work/human-study/manifest.json --input=work/human-study/exports --out=outputs/human-study-check-01 --require-gates
```

报告目录必须尚不存在，防止覆盖历史证据。无需联网或上传；工具只读取名单声明的 JSON。每份最多 2 MiB、每人 10 份、每批 120 份；缺失文件会报警并保留参与者在分母。格式错、版本混合、自动化标记、跨人重复局、答案不符或快照冲突会报错，**不静默丢弃坏数据来提高结果**。解决时保留原件和排除理由，不手工修写成绩。

输出 `summary.json`（逐人和总体结果、输入哈希）、`report.md`（可读报告）、`review-budget.json`（逐段复盘字数）。相同输入和观察截止时间会给出同一统计。退出码：`0` 表示成功生成报告，不等于验收通过；`1` 表示输入/文件错误；加 `--require-gates` 后，数值不达标或数据不足返回 `2`。工具永远保留 `releaseDecision: pending-human-review`。

未填名单也可演练，使用模板会输出 0 人、`insufficient-evidence`；不能把它当成 12 人报告。历史 `e05-automated-sample-*.json` 明确标记为自动化，工具会拒绝纳入真人批次。

## 预先固定的统计口径

- 每人首局一次；完整七关数 / 纳入人数（含已同意但未交记录者），至少 12 份有效零基础首局才判断门槛。12 人中 9 人完整通关才达到 ≥70%。任意结局、局中重开、终局后重开、额外局分别报告；练习和无本地开局的导入局不能算首局。
- 六题原始分差 ×100/6 得到每人的百分点提升，再取中位数，不能拿均分差或相对增长率代替。只对完整前后配对计算，跳过/缺失不算零分。本包增加采集充分性约定：**至少 12 对才自动判定 ≥20 个百分点门槛**；不足只报告观察值并标数据不足。需补招时保留原批所有纳入者，不为凑数删除低分或未完成者。
- 正常通关首局的经营有效时长中位数目标 30–45 分钟；从活动时钟扣除完整前测与终局后测/补学。缺边界明细不估算，必须补证；提前终局不计入正常完成时长。各关原始时长仍包含发生在该关的测评/复盘，用于定位负担。
- 计时只在可见、有焦点且两分钟内有输入时累计，不能代表墙钟时间或完全准确的阅读时间。各关阅读停顿由人工观察补充；最后不足 5 秒可能因突然关闭而丢失。
- 截止时 ≥24h 未完成且无结局/重开，才标“观察流失”；这是导出快照的观察，须人工确认未提交的恢复。重开、正式丢单/破产不是关页流失。
- 快照累计计数取最新值而非相加；事件 ID 去重。被裁剪的明细不得虚构，事件类型分布与复盘阅读只代表已保留记录。达到容量上限须备注。
- 数值达标后仍须逐条关闭/解释 12 人反馈、核对复盘 ≤120 字、专业顾问签核和现有工程门禁。工具不能自动宣布 G4 或发布完成。

## 隐私与保存

JSON 不需要真实姓名、联系方式或实际贸易单据；反馈截图请遮盖私人信息。只有经同意的组织者查看原始文件，报告引用匿名编号。建议告知保存 30 天用于问题复核，之后按约定删除原始记录；撤回时移出汇总并标记 `withdrawn`，不重用编号。此约定由组织者执行，不新增账号、云存档或远程埋点。
